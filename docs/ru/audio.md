# Автоматический звук активной VR-игры

[English](../en/audio.md) · [Запуск](usage.md) · [Проверки сборки](development.md)

8 октября 2026 пользователь подтвердил, что звук в исходной установке исправлен. В репозиторий перенесена реализация выбора активной сцены. Полная установка на другом Mac и переключение между произвольными VR-играми остаются непроверенными.

## Обновление существующей установки

Из локального checkout проекта, если нет незакоммиченных изменений:

```sh
git pull --ff-only
./scripts/stop.sh
./scripts/build_adapter.sh
./scripts/configure.sh
```

Если меняли каталог установки, добавляйте прежний `--root PATH` к каждому скрипту. Обновление предназначено для установок, созданных скриптами этого репозитория; чужую оболочку они отклонят. Build собирает без установки и захвата. Configure сохраняет бэкапы адаптеров/plist/настроек, устанавливает новый bridge и `C:\ALVR\AudioSceneWatcher.exe`, включает Game audio и записывает scene-mode exports в оболочку. Сохранённый профиль и привязанные клиенты сохраняются. Steam после этого остаётся остановленным.

Запустите всё через [обычный Steam](usage.md#обычный-запуск-через-steam). Game audio должен быть включён до игры. Отдельная app на каждую игру и ручной выбор `audio-source.pid` больше не нужны. Не смешивайте новый bridge с другой версией watcher или Wine.

## Что изменилось

1. Аудиотаблица Wine регистрируется независимо от готовности графики: GUI-запуску не нужно дожидаться графического hook для перехвата звука.
2. Фоновый OpenVR-наблюдатель проверяет существующий vrserver и читает `GetCurrentSceneProcessId`. Он не запускает игры и не забирает фокус сцены/ввода.
3. Bridge переводит Windows→native PID через точный закреплённый протокол Wine, проверяет время создания, пользователя, prefix и имя executable. Устаревшие и чужие наблюдения отклоняются.
4. Приватный stereo CoreAudio tap создаётся с пустым списком включённых процессов. Он следует за проверенной игрой и сохраняет UID/ASBD при смене источника. Общий звук Mac и микрофон не подхватываются; обычный звук Mac не глушится.
5. Смена источника согласуется с Wine Stop/Reset и проверками выданных буферов. Пустой `GetNextPacketSize` тоже запускает поиск сцены: иначе CPAL мог не дойти до GetBuffer и никогда не обнаружить игру. При неудачной проверке адаптер не выдаёт управляемый PCM и не выбирает случайный источник.

Предусмотрена последовательность idle → игра → idle → новая игра; её покрывают fake-тесты. Подтверждение слышимого звука пользователем не доказывает каждое переключение и каждую игру в реальном шлеме. Звук из отдельного вспомогательного процесса пока не связывается с игрой автоматически.

## Диагностика и восстановление

```sh
./scripts/audio_status.sh
./scripts/doctor.sh
```

Audio status читает только состояние наблюдателя собственного работающего vrserver. `ready=1` подтверждает сопоставление процессов, а не доставку PCM или слышимый звук. Смотрите возраст наблюдения: файл может остаться после завершения наблюдателя. Пока подходящая игра не запущена, `ready=0` и пустой источник ожидаемы. Без активного клиента ALVR аудиоколбэки могут ещё не вызываться.

Разрешите захват звука для оболочки/терминала, указанных macOS. При `0x80004001` проверьте версии, guards и загрузку адаптера: сам код не устанавливает причину. Небезопасное состояние tap или ошибка Stop/Reset требуют остановки своей бутылки и нового запуска. Не убирайте проверки и не уничтожайте устройство, которым ещё пользуется Wine. См. [FAQ](faq.md).

Аудиобуфер клиента остаётся average 50 мс/batch 10 мс, ёмкость host capture — 100 мс. Для аудиоисправления не нужны другие значения видео, битрейта, pacing, герцовки и MSAA. Configure повторно применяет профиль из `settings.json`; ручные правки в Dashboard, не отражённые в нём, могут быть перезаписаны. Перед configure проверьте сохранённый профиль. Эти параметры описаны [отдельно](settings.md).
