# Менять настройки по одной

[English](../en/settings.md) · [FAQ](faq.md)

Параметры хранятся в приватном каталоге установки. Запись при работающем prefix отклоняется. `--restart` явно останавливает/перезапускает **эту** бутылку. Если важен прогресс, сначала сохранитесь.

```sh
./scripts/settings.sh
./scripts/stop.sh
./scripts/settings.sh --msaa 4
./scripts/launch_alyx.sh
# Или с явным перезапуском:
./scripts/settings.sh --msaa 2 --restart
```

| Аргумент | Что меняет | Сейчас |
|---|---|---|
| `--msaa 2` / `--msaa 4` | Игровой `+vr_msaa VALUE`; проверенные варианты | 2 |
| `--hz 72` / `--hz 90` | Номинальную частоту шлема/драйвера/кодека | 72 |
| `--bitrate 300` | Цель для сжатого stereo-видео, Мбит/с; не на глаз | 300 |
| `--threads 10` | Потоки SW-кодека, а не всех стадий | 10 |
| `--packet-size 16384` | TCP-блок, не IP MTU; допускаются 1400/16384 | 16384 |
| `--pacing off` | Убирает server nominal-vsync sleep | off |
| `--ffr on` | Широкая область fixed foveated encoding | on |
| `--eye 1632 1632` | Рекомендацию рендера и цель до FFR на глаз; кратность 32 | 1632² |
| `--profile current` | Последний выбранный профиль 72Гц | current |
| `--profile performance90` | Профиль с более высокой измеренной кадровой частотой | опция |

## MSAA задаётся аргументом запуска

В обычных настройках Alyx этой ручки нет. Передаём `+vr_msaa 2` с auto-fidelity off и level 3. `-msaa2` и ранние строки консоли не доказывали активный режим: исходный эксперимент использовал guarded read-only probe. Публичный launcher сохраняет значение и передаёт его при каждом старте без правки DLL игры.

## Pacing и герцовка

90Гц — такт 11,1мс; 72Гц — 13,9мс. Pacing on ждёт расчётной отметки после Present. Off разрешает производить быстрее, но медленная доставка может не успеть.

С TCP 1400 отключение pacing давало локальные дропы и рост задержки. На 90Гц/16КиБ A/B/A получился примерно 45,5→70,5→45,5 новых видеокадров/с с сопоставимой задержкой и без queue-full в этих окнах.

72Гц не улучшили наши цифры: прежние 300Мбит/с дали кодеку больший бюджет на кадр через nominal framerate/VBV. Размер сжатого кадра вырос примерно 25%; encoder-stage стал 16,6мс вместо 12,9, доставка упала до 55/с. Пользователь оставил 72Гц. Компенсацию 240Мбит/с при 72Гц **не проверяли**.

## Разрешение и сжатие

Рендер — 1632×1632 на глаз. FFR с центром 0,7/edge ratio 2 даёт закодированный stereo-холст 2816×1408. Окно 1920×1080 на Mac не доказывает VR-input 1080p.

Остаётся software H264 ultrafast/zerolatency, all-I, без B-frames. Hardware VideoToolbox не включён. Битрейт улучшал чёткость, но добавляет нагрузку доставке/декодеру. Потоки не ускоряют автоматически Map/конверсию. FIFO 2 ограничивает только одну очередь.

Отдельные проверки:

```sh
./scripts/settings.sh --profile performance90 --restart
./scripts/settings.sh --pacing on --restart
./scripts/settings.sh --ffr off --restart
./scripts/settings.sh --eye 2048 2048 --restart
```

Сравнивайте одинаковый save/сцену и похожие движения головы, закончите центровку до замера. Новые кадры декодера — не чистый GPU FPS игры.

Если запускаете обычной кнопкой «Играть» в Steam, перенесите нужный `+vr_msaa VALUE` и фиксированный fidelity в параметры запуска игры, как в [инструкции](usage.md). Скрипт настроек меняет предпочтения нашего launcher, а не файлы аккаунта Steam.
